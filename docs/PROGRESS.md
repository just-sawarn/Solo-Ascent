## Milestone 2: Renderer: DONE (first pass; see gaps)
Delivered (`src/render`): GLSL ES 3.00 toon shader with a generated ramp texture (per-look), PCF shadow map (packed RGBA8 depth: no depth-texture extension needed, texel-snapped to stop shimmer), inverted-hull outlines (pixel-constant thickness, radial-normal trick for hard-edged cubes), hair highlight band, stylized specular + rim light, height fog, procedural sky/stars/moon, half-res bloom with an emissive mask in alpha, FXAA-lite, ACES, grading, vignette. 5 quality tiers (ULTRA..MOBILE: shadow res, PCF radius, render scale, bloom passes, FXAA) plus a governor: benchmarks on start (steps down until under ~19 ms) and drops a tier after 3 s of sustained >22 ms; it never raises quality on its own. Three looks, switchable live with 1/2/3: *Shadow Monarch* (Solo-Leveling-style), *Bright Adventure*, *Dawnbrand* (my pick; see `docs/screenshots/`). Procedural placeholder characters (party, shadow soldiers) and ruins in `src/world/test_scene.c`. URL query `?look=1-3&tier=ultra..mobile&still=1` drives the build for tests/screenshots.

NOT done yet (deferred, in order of when they land): cascaded shadows (single 28 m ortho map for now), GTAO/SSAO, SSR and cubemap probes, planar water reflections, volumetric fog/god rays, lightmaps/light probes, DoF/motion blur (cutscenes), FSR-style upscaler and dynamic resolution (tiers use a fixed render scale), instancing/culling/LOD (matters with real content: M9), KHR_parallel_shader_compile (raylib compiles shaders synchronously; there are only 7 fixed programs, compiled at startup, no permutations). The scene RT is 8-bit (colors stored gamma-encoded) because float render targets need EXT_color_buffer_float; a float path is a later optimisation. Warm-up: shaders are compiled/linked in `renderer_init`; the first frame still pays one-time driver costs behind the start screen.
Verified: builds with zero warnings in our code; smoke test passes (debug and release); screenshots reviewed. NOT verified: real GPU/phone performance. Headless software GL runs the MEDIUM tier at ~110 ms/frame, which says nothing about real hardware; the smoke benchmark baseline was reset for the new scene.

## Milestone 2.5: CC0 character pipeline (first pass)
Quaternius *Universal Base Characters [Standard]* (CC0; only the Superhero male/female bodies and 5 hairstyles are in the free pack) loads through raylib's glTF path with GPU skinning (`character.c`): CPU pose evaluation from world-axis bone rotations, 65-bone skin matrices, outfit colours painted onto body regions in the shader (`RM_PAINT`: top/bottom/shoes by bind-space region, flat anime skin), hair rigid on the head bone, overlay parts (coat, sleeves, sneakers, CC0 short sword) riding on bones. `heroes.c` builds Kael this way. Assets are prepped by `tools/prep_characters.py` (512 px textures, normal maps dropped).
Found and worked around a raylib bug: on WebGL `rlSetUniformMatrices` cannot transpose, so bone matrices arrive transposed; we transpose them on web (`character.c`). Also fixed a per-frame material leak in the renderer (materials are now created once).
Known gaps: face/eyes are the pack's realistic ones (not anime yet: needs an anime face texture or overlay eyes), body is the "superhero" build slimmed by non-uniform scale, coat is simple cone panels, the pack has NO animations (needs Quaternius *Universal Animation Library*, also CC0), Bram/Lyra/Mirelle/NPCs still use the old primitive builder, bone uniforms use 72 mat4 (a bone-texture path is safer for low-end mobile GPUs), release `index.data` is 3.7 MB (move to streamed bundles in the pipeline milestone).

## Milestone 5: Party system, companion AI, role mechanics: DONE (first full pass; see gaps)
Core (native-tested, 9 suites): `party.c` gives all four members (Kael, Bram, Lyra, Mirelle; defined in `data/party.json` with stats, known skills, slot bindings) one shared cast/move path. The controlled member is driven by human input, the others by `companion_ai.c`, which emits the same kind of input (move vector, guard, roll, skill + target). Companion AI per role: **Tank** taunts when an ally is hunted, bashes casting enemies, raises guard so the hit lands inside the parry window, iron wall / barriers / ground slam by situation, holds a line between enemies and the party; **Mage** kites to ~8.5 m, picks frost lance / fireball / AoE by cluster size, manages mana, shields itself, uses ice nova as a panic button, dodges melee wind-ups; **Healer** triages (purify curse, cleanse, revive when safe, single / big / area heals by thresholds), buffs at fight start, attacks only when everyone is fine. Commands: **Aggressive** (engage anything), **Defensive** (only enemies near the leader or attacking someone), **Support** (stay close, heal/buff first, no fights started). Threat/aggro: damage builds threat (tank x2.5), healing draws attention, taunt forces focus; enemies target by highest threat and fall back to nearest. Control switching (R, 5-8, D-pad, SWAP button), auto-switch when the controlled member falls, party wipe respawn.
Presentation: Bram, Lyra, Mirelle on the CC0 male/female bodies with outfit paint and overlay parts (cuirass, pauldrons, round shield, long sword; witch hat, twin tails, robe, glowing staff; halo, stole, long robe, staff), animations by skill (spell clips for casters), party frames with HP/MP/status/role, command indicator, skill bar for whoever you control, camera hand-over smoothing.
Tests: headless full-party fight vs 9 leveled-up enemies (all dead, no deaths, tank absorbs most damage, healer heals, mage stays out of melee, taunt used), command behaviour (aggressive advances, defensive holds, support heals and starts nothing), revive when safe, curse purge, switching, wipe/respawn. Browser smoke: followers keep up, B/R/5/8 work, the party kills a brute with no losses.
NOT verified: how it feels to play (AI timing, difficulty), gamepad/touch for switching. Gaps: companions steer straight at goals with physics sliding (no navmesh; fine in the open sandbox, will get stuck behind complex geometry), no bond/affinity or combo-link mechanics yet (Milestone 7 with dialogue/bond data), Lyra/Mirelle/Bram have no VFX for spells (Milestone 9), companions' signature skills (Unbroken Vow etc.) are only used by simple triggers, enemy count/encounters are still the sandbox set.

## Milestone 8: Asset pipeline, streaming, PWA: DONE (first pass; see gaps)
- `tools/pack_assets.py` (run by the `sa_packs` CMake target after every web build) builds content-addressed packs (`packs/<name>.<hash8>.pak`, format "SAPK") and `packs.json` (size + sha256 + `boot` flag), and stamps `sw.js` with a build id so each build installs a fresh service worker. Preloaded `index.data` shrank from 6.9 MB to 0.74 MB (data JSON only); models/animations moved to packs.
- `web/glue.js`: boot packs download in `preRun` (run dependency) with a byte-accurate progress bar, SHA-256 verification (a corrupt cached entry is evicted), 3 tries with backoff, and a visible error plus Retry if they still fail. On-demand streaming API for the C side: `platform_pack_request/state` (native build: always ready).
- `web/sw.js`: core cache per build (cache-first), shared immutable pack cache (pruned to the packs listed in `packs.json`), network-first for the page and `packs.json`; install precaches the core and boot packs so the game starts offline after one visit. A new build shows an in-page "Reload" notice instead of forcing a reload mid-game. Storage persistence requested on start; quota is reported in `__sa.storage`.
- Tests: `tools/smoke_pwa.mjs` (boot packs mounted, C-requested pack streamed into the FS, SW core + pack caches, offline reload reaches the title, corrupt pack fails loudly). Existing smoke passes on debug and release.
Gaps: no region packs yet (they arrive with M9; the mechanism is proven with a self-test pack), no texture compression (KTX2/Basis) because textures are tiny palettes, no audio assets yet (M11), update-notice flow not browser-tested (needs two builds), `scripts/package.sh` output not tried on a real host or real phone.
