## Milestone 2: Renderer: DONE (first pass; see gaps)
Delivered (`src/render`): GLSL ES 3.00 toon shader with a generated ramp texture (per-look), PCF shadow map (packed RGBA8 depth: no depth-texture extension needed, texel-snapped to stop shimmer), inverted-hull outlines (pixel-constant thickness, radial-normal trick for hard-edged cubes), hair highlight band, stylized specular + rim light, height fog, procedural sky/stars/moon, half-res bloom with an emissive mask in alpha, FXAA-lite, ACES, grading, vignette. 5 quality tiers (ULTRA..MOBILE: shadow res, PCF radius, render scale, bloom passes, FXAA) plus a governor: benchmarks on start (steps down until under ~19 ms) and drops a tier after 3 s of sustained >22 ms; it never raises quality on its own. Three looks, switchable live with 1/2/3: *Shadow Monarch* (Solo-Leveling-style), *Bright Adventure*, *Dawnbrand* (my pick; see `docs/screenshots/`). Procedural placeholder characters (party, shadow soldiers) and ruins in `src/world/test_scene.c`. URL query `?look=1-3&tier=ultra..mobile&still=1` drives the build for tests/screenshots.

NOT done yet (deferred, in order of when they land): cascaded shadows (single 28 m ortho map for now), GTAO/SSAO, SSR and cubemap probes, planar water reflections, volumetric fog/god rays, lightmaps/light probes, DoF/motion blur (cutscenes), FSR-style upscaler and dynamic resolution (tiers use a fixed render scale), instancing/culling/LOD (matters with real content: M9), KHR_parallel_shader_compile (raylib compiles shaders synchronously; there are only 7 fixed programs, compiled at startup, no permutations). The scene RT is 8-bit (colors stored gamma-encoded) because float render targets need EXT_color_buffer_float; a float path is a later optimisation. Warm-up: shaders are compiled/linked in `renderer_init`; the first frame still pays one-time driver costs behind the start screen.
Verified: builds with zero warnings in our code; smoke test passes (debug and release); screenshots reviewed. NOT verified: real GPU/phone performance. Headless software GL runs the MEDIUM tier at ~110 ms/frame, which says nothing about real hardware; the smoke benchmark baseline was reset for the new scene.

## Milestone 2.5: CC0 character pipeline (first pass)
Quaternius *Universal Base Characters [Standard]* (CC0; only the Superhero male/female bodies and 5 hairstyles are in the free pack) loads through raylib's glTF path with GPU skinning (`character.c`): CPU pose evaluation from world-axis bone rotations, 65-bone skin matrices, outfit colours painted onto body regions in the shader (`RM_PAINT`: top/bottom/shoes by bind-space region, flat anime skin), hair rigid on the head bone, overlay parts (coat, sleeves, sneakers, CC0 short sword) riding on bones. `heroes.c` builds Kael this way. Assets are prepped by `tools/prep_characters.py` (512 px textures, normal maps dropped).
Found and worked around a raylib bug: on WebGL `rlSetUniformMatrices` cannot transpose, so bone matrices arrive transposed; we transpose them on web (`character.c`). Also fixed a per-frame material leak in the renderer (materials are now created once).
Known gaps: face/eyes are the pack's realistic ones (not anime yet: needs an anime face texture or overlay eyes), body is the "superhero" build slimmed by non-uniform scale, coat is simple cone panels, the pack has NO animations (needs Quaternius *Universal Animation Library*, also CC0), Bram/Lyra/Mirelle/NPCs still use the old primitive builder, bone uniforms use 72 mat4 (a bone-texture path is safer for low-end mobile GPUs), release `index.data` is 3.7 MB (move to streamed bundles in the pipeline milestone).

## Milestone 3 (started): animation
Quaternius *Universal Animation Library [Standard]* (CC0) converted by `tools/prep_animations.py` to a 1.9 MB `.sanim` (32 clips @30 fps, int16 quats). `anim.c` plays clips with crossfades; `character_pose_anim` builds the skeleton from local TRS and layers optional world-axis bone tweaks. Kael runs a small locomotion state machine (idle / walk / jog / sprint by speed, sword attack, roll) driven from the game loop; WASD move, Shift sprint, Ctrl walk, J or right-click attack, Space roll. Verified by screenshots in headless Chromium (sprint cycle, attack swing). Not yet: animation events/hit windows, root motion, foot IK, blend trees with phase sync (walk<->jog blends can foot-slide), animation retargeting for the female body is untested (same rig names; should work), no unit test for anim.c (it needs raylib file loading; extract the sampler into core when combat needs it).

## Milestone 4: Combat: DONE (first full pass; see gaps)
Data: `data/skills.json` (44 playable skills: hero 14, tank 10, mage 10, healer 10, plus the hero's 3-hit combo and 4 enemy skills; story ids such as `heroic_slash`, `flame_parry`, `sunder`, `gale_rush`, `dawn_arc`, `taunt`, `unbroken_vow`, `starfall`, `radiant_renewal`) and `data/enemies.json` (shadow soldier / archer / brute), loaded with cJSON and validated (unique ids, hit before end, known statuses/skills).
Rules (`core/combat.c`, native-tested): derived stats from level + 5 stats, damage = stat x power x 100/(100+def) x element x variance x crit, six elements with per-enemy resistances, guard (-60% damage) and perfect parry (0.2 s window: no damage, attacker staggered), poise/stagger that interrupts casts, 12 statuses (burn, poison, slow, stun, silence, Hollow Curse that blocks healing, taunt, buffs, defense break, regen, mana regen), barriers, cast timing (windup -> effect -> recovery), 11 skill kinds (arc, dash, area, projectile with splash and wall stops, heal, area heal, buff, barrier, taunt, revive, cleanse), Resolve passive, Resonance Gauge, deterministic RNG, event stream.
AI (`core/enemy_ai.c`): aggro, chase, telegraphed attacks through the same combat rules, archers kite and need line of fire, brutes slam with big poise, taunt override, leash and return, separation.
Game side: 3-hit combo with input buffering, skill slots 1-4, guard, dash application, hit-stop, camera shake, white hit flash, floating damage numbers, enemy/lock-on health bars, player vitals, skill bar with cooldowns, respawn, enemy actors on the CC0 rig with hit/death/attack clips and data-driven paint; touch buttons for skills and guard; gamepad skill modifier (LT).
Verified: 8 native suites under ASan/UBSan (combat tests cover formulas, gating, timing, arcs, areas, guard/parry/barrier, poise, statuses, projectiles, revive, taunt, resolve, i-frames, dash, gauge, crit statistics, determinism); browser smoke fights an enemy to death in the real build; screenshots reviewed. NOT verified: how combat feels (timings, damage tuning are first guesses), gamepad/touch combat on real devices.
Gaps: only the hero's skills are wired to inputs (tank/mage/healer skills run in the core and tests but have no companion AI yet: Milestone 5), no enemy-specific animations beyond the shared clips, no VFX/particles for spells yet (Milestone 9), hit windows use the skill's hit_time rather than animation events, no weapon trails, no audio.
